# События, DoR / DoD и ретроспектива

## Definition of Ready (история готова к взятию в спринт)

- [ ] Сформулирована как «Как *роль*, я хочу *действие*, чтобы *польза*».
- [ ] Есть критерии приёмки (Given / When / Then), понятные PO и команде.
- [ ] Оценена командой; ≤ 8 SP (иначе разбить).
- [ ] Зависимости известны (API, доступы, макеты); нет неразрешённых блокеров.
- [ ] Для UI есть макет или согласованный эскиз.

## Definition of Done (инкремент)

- [ ] Код прошёл ревью (парное программирование или Pull Request с ≥ 1 одобрением).
- [ ] CI зелёный: линтер, юнит- и интеграционные тесты; покрытие новых строк ≥ 80 %.
- [ ] Критерии приёмки проверены (автоматически или по чек-листу QA).
- [ ] Контракт OpenAPI и README обновлены.
- [ ] Развёрнуто на staging, нет известных критических дефектов.
- [ ] PO принял историю.

## Повестки событий

**Sprint Planning (4 ч, день 1).**
1. PO представляет цель продукта и приоритеты (15 мин).
2. Команда формулирует Sprint Goal и выбирает истории по ёмкости (1 ч 45 мин).
3. Декомпозиция на карточки, договорённость о WIP-лимитах, первые «пары» (2 ч).

**Daily Scrum (15 мин, 09:30).** Не статус-репорт руководителю, а план команды: «Что продвигает нас к цели сегодня? Что мешает?»
Доска открыта на экране; сначала смотрим правую часть (Review/Testing), затем левую. Обсуждения глубже 2 минут уходят «после Daily».

**Backlog Refinement (1 ч, день 5).** Критерии приёмки и оценка PB-07…PB-09; разбиение крупного (PB-10).

**Sprint Review (1 ч, день 10).** Демо на staging: вход → вступление по ссылке → переписка двух пользователей в реальном времени.
Присутствуют PO, староста ПИ-21, представитель деканата. Результат: обратная связь, правки бэклога, пересмотр дат релиза.

**Retrospective (1 ч, день 10).** Формат «Start / Stop / Continue» + одно конкретное улучшение с владельцем и сроком.

## Чек-лист ретроспективы (вопросы)

- Где у нас копится очередь, почему? (смотрим CFD и время в колонках)
- Что из XP помогло сильнее всего: пары, CI, малые релизы? Что мешало?
- Достигли ли Sprint Goal? Если нет, что решили урезать и вовремя ли?
- Были ли овертаймы? Что ослабило Sustainable Pace?
- Какое **одно** изменение процесса проверим в спринте 2 и как поймём, что оно сработало?

Кандидаты улучшений: общий лимит «ревью за 4 часа»; чек-лист приёмки заранее вместе с PO; автоматизировать приёмочные проверки (Света);
сделать «дежурного ревьюера» на день.

## Рабочие договорённости

* Решения по процессу принимаются командой на Daily/Retro; Scrum Master не раздаёт задачи.
* Красный `main` — приоритет №1.
* Овертаймы и ночные деплои не используем; при риске срыва обсуждаем объём с PO.
